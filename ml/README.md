# DetectIQ ML Pipeline

## Overview

This directory contains the machine learning component of DetectIQ's multi-layer phishing detection system.

**Model**: TF-IDF Vectorizer (word n-gram 1-2 + char n-gram 3-5) + Logistic Regression  
**Dataset**: [zefang-liu/phishing-email-dataset](https://huggingface.co/datasets/zefang-liu/phishing-email-dataset) (Hugging Face)  
**License**: LGPL-3.0  
**Purpose**: Text-based phishing classification for email, SMS, and WhatsApp messages

> **Important**: This ML model is trained on email text. It is **NOT** used to classify URLs — URL reputation is handled by the heuristic engine and threat intelligence (PhishTank/URLhaus).

## Quick Start

### Prerequisites
- Python 3.8+
- pip

### Installation

```bash
cd ml
pip install -r requirements.txt
```

### Step 1: Download Dataset

```bash
python ml/download_dataset.py
```

This downloads `zefang-liu/phishing-email-dataset` from Hugging Face (~18,650 rows) to `ml/data/`.

### Step 2: Train the Model

```bash
python ml/train.py
```

This:
- Deduplicates and preprocesses the dataset
- Performs an 80/20 stratified train/test split (seed=42)
- Fits TF-IDF vectorizers on training data only
- Trains LogisticRegression(class_weight='balanced')
- Evaluates on held-out test set
- Saves artifacts to `ml/artifacts/`
- Saves evaluation metrics to `ml/reports/evaluation.json`
- Saves confusion matrix plot to `ml/reports/confusion_matrix.png`

### Step 3: Start the Inference Service

```bash
# From project root:
python -m uvicorn ml.api.main:app --host 0.0.0.0 --port 8001

# Or from ml/ directory:
uvicorn api.main:app --host 0.0.0.0 --port 8001
```

### Step 4: Run Classifier Tests

```bash
python ml/tests/test_classifier.py
```

## Model Architecture

### Algorithm
**TF-IDF + Logistic Regression** — intentionally chosen for:
- Fast inference (<1ms per prediction)
- Explainability (feature weights interpretable)
- Probability estimates via `predict_proba`
- Deterministic results
- Suitable for college-level security project
- No GPU required
- Locally runnable

### Feature Extraction

Two TF-IDF vectorizers are combined using horizontal stacking:

| Vectorizer | n-gram range | max_features | Notes |
|-----------|-------------|--------------|-------|
| Word n-gram | (1, 2) | 30,000 | Captures unigrams + bigrams |
| Char n-gram | (3, 5) | 20,000 | Captures character-level patterns (obfuscation-resistant) |

Character n-grams capture patterns like `v3r1fy`, `acc0unt`, URL fragments embedded in text.

### Classifier

```python
LogisticRegression(
    C=1.0,
    class_weight='balanced',   # Handles class imbalance
    max_iter=1000,
    random_state=42,
    solver='lbfgs',
)
```

`class_weight='balanced'` automatically adjusts weights inversely proportional to class frequency, preventing the model from biasing toward the majority class.

## Dataset

| Property | Value |
|---------|-------|
| Source | [zefang-liu/phishing-email-dataset](https://huggingface.co/datasets/zefang-liu/phishing-email-dataset) |
| License | LGPL-3.0 |
| Approximate size | ~18,650 labeled emails |
| Labels | Safe Email, Phishing Email |
| Train split | 80% (stratified) |
| Test split | 20% (held-out) |
| Random seed | 42 |

### Preprocessing

Applied to both train and test data using the same function (no leakage):
1. Lowercase
2. Strip HTML tags (email body noise)
3. Collapse repeated punctuation (`!!!` → `!`)
4. Collapse whitespace runs

**Preserved intentionally** (phishing signals):
- URLs and domains
- Numbers (amounts, OTPs, phone numbers)
- Urgent vocabulary
- Credential-related terms

## Security

- Submitted text is **never executed**
- Submitted text is **never stored** (only in-memory vector used)
- Input is validated: non-empty, max 10,000 characters
- Stack traces are suppressed in error responses
- No API keys are exposed

---

## Limitations

- Model trained on email data — may underperform on very short SMS messages
- Does not understand images, attachments, or visual spoofing
- "Safe" prediction = no phishing-like language detected — not a guarantee of safety
- Cannot detect zero-day phishing using novel language not seen in training data
- Should be used alongside heuristic engine and threat intelligence (not as sole detector)

---

## Honest Evaluation Note

The evaluation metrics reported in `ml/reports/evaluation.json` were computed on **held-out test data that was never seen during training**. They represent the actual performance of the trained model. No metrics have been fabricated or estimated.
